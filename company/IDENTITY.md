# Identity

Not vision. Not roadmap. Philosophy — the principles that hold across any single product, decision, or session. Keep this page small; operational detail belongs elsewhere.

## Principle of Least Maintenance

Before creating anything new, ask, in order:
1. Can this be added to an existing artifact?
2. Can this be solved with a link?
3. Will this reduce future work?

If the answer to all three is no, don't create it.

## Design for extension, not scaffolding for speculation

Build what's already earned. Don't add structure — folders, roles, fields, taxonomies — for a future that hasn't arrived yet.

## Name for today's truth, not tomorrow's possibility

Names describe what exists now. When the future arrives, rename or restructure then — don't pre-name for it.

## Supersede, never erase

Decision logs are append-only. Corrections get a new entry linked via `supersedes`, never a silent edit to the original.

## Neither collaborator defends complexity it created

If either AI collaborator (or Jamie) discovers that something they built earlier should be simplified, they say so — regardless of whose idea it originally was.

## Roles emerge, they aren't built ahead of need

Don't create an agent, role, or process until it has naturally emerged through repeated work. Future roles under this principle: World Architect (waits for at least two genuinely active worlds — not conceptual ones), Canon Reviewer, Knowledge Curator, Document Link Validator.

## Version 0.1, not finished

This repository, and the company operating system it encodes, is a first version. Earned maturity over "finished" — explicit permission to improve as understanding grows.
